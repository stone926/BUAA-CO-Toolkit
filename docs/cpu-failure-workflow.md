# 自动测试失败后的排查流程

## 交互设计

用户路径：持续测试 / 测试历史 → 定位失败 → 查看证据 → 修改 CPU → 重跑此用例。

- 失败即停后，持续页突出首个问题和「定位失败」；历史的失败 / 错误记录提供相同入口。
- 用一个诊断页说明测试判定、首个可观察差异与下一步。对拍并列参考和 CPU 的 PC、目标、值；P7 定向检查保留场景诊断及特殊范围说明。没有证据时明确说明，不从诊断字符串猜测根因。
- 「定位汇编」使用该用例保存的 ProgramImage/source graph 映射；「对比写回」打开已保存的参考和 CPU trace。源码与 trace 行号分别处理，不能混用。
- 「重跑此用例」使用原程序闭包、输入与 P7 元数据，检查当前 CPU；创建独立记录，保留原失败证据。「重跑并看波形」只对 Verilog CPU 提供，复用自动测试 TB 和预算，按需生成 VCD。
- 高级入口渐进展示：流水线冲突分析是理论参考，用于排查转发 / 阻塞，不冒充 DUT 波形或 P7 外设复现。
- 不新增用户设置；重跑可取消，有进度和明确结果。通过只说明这个用例当前通过，可以再启动持续测试扩大检查。

## 实现边界

解析 / 定位证据与页面渲染、文件读取、重跑业务、VS Code 消息 glue 分离。持续测试只额外保存有界首差异导航证据；打开详情时才读指定用例的源码、image 和 trace。缺失或损坏的单个产物不应阻止其他证据展示。

Webview 只发送宿主持有范围内的 case ID 和固定动作，不接收任意文件路径或命令。文件操作复用 containment、bounded read 和 snapshot hash 验证。新旧结果不混写，旧版无定位证据的记录保留诊断与明确降级提示。
